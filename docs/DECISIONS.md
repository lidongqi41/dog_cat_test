# 决策记录（ADR）

记录「为什么这么定」，避免后来的会话或人凭直觉推翻已定方案。
每条决策包含：状态、背景、决定、理由、代价与回退方式。

状态取值：`已定`（执行中）、`待定`（有争议，需要决定）、`已废弃`（被后续决策取代）。

---

## ADR-001 技术栈：原生小程序，不引入跨端框架

- **状态**：已定
- **日期**：2026-11-05
- **背景**：项目由微信开发者工具的「空白模板」创建，只有一个首页骨架。
- **决定**：用原生 WXML / WXSS / JS 开发，不引入 Taro、uni-app、mpvue 等跨端框架。
- **理由**：只有一个平台需求；原生方案没有编译层，调试信息和报错直接对应源码；包体积最小；新特性（Skyline、glass-easel）第一时间可用。
- **代价**：将来如果要出 H5 或 App，需要重写界面层。
- **回退**：真要跨端时，业务逻辑放在 `utils/` 里保持纯 JS，迁移成本可控。

## ADR-002 渲染引擎：Skyline + glass-easel

- **状态**：已定（可回退）
- **日期**：2026-11-05
- **背景**：模板默认开启了新渲染引擎。
- **决定**：保留 `"renderer": "skyline"`、`"componentFramework": "glass-easel"`，基础库 3.17.6。
- **理由**：Skyline 是原生渲染，长列表、手势、动画的性能和一致性优于 WebView 渲染；模板已按它写好（`scroll-view` 带 `type="list"`）。
- **代价**：CSS 只支持子集，不能使用 `document` / `window`，部分老写法（如某些 `position: fixed` 组合）表现不同。
- **回退**：`app.json` 改 `"renderer": "webview"` 即可，但样式需要重新适配，**不要两种模式混用**。

## ADR-003 导航栏：全局自定义（navigationStyle: custom）

- **状态**：已定
- **日期**：2026-11-05
- **决定**：`app.json` 使用 `"navigationStyle": "custom"`，由 `components/navigation-bar` 自绘顶部栏。
- **理由**：需要控制胶囊按钮两侧留白、状态栏高度、安全区；原生导航栏无法满足自定义视觉。
- **代价**：必须自己处理 `safeArea`、`getMenuButtonBoundingClientRect`，Android / iOS / 开发者工具三套差异；组件缺 `home` 方法（见 HANDOFF 的已知问题）。
- **回退**：删掉 `navigationStyle`，页面里移除 `<navigation-bar>`，回到原生导航栏。

## ADR-004 分支模型：main 可发布 / dev 日常 / feature 短分支

- **状态**：已定
- **日期**：2026-11-05
- **决定**：
  - `main`：只放可发布版本，只接受从 `dev` 快进合并
  - `dev`：日常开发分支，功能完成后合并进 `main`
  - `feature/xxx`：单个功能，做完合回 `dev` 并删除
- **理由**：单人也能靠 `main` 一眼看出「线上是哪一版」；`feature` 分支让一个功能可以中途放弃而不污染 `dev`。
- **代价**：多一步合并操作；忘切分支时容易在 `main` 上直接提交（GitHub 侧有保护规则兜底历史，但不阻止直接提交）。

## ADR-005 历史必须线性，main 禁止 merge 提交

- **状态**：已定
- **日期**：2026-11-05
- **决定**：合并一律 `--ff-only`（main）或 `--no-ff`（feature → dev）；`main` 上不出现 merge commit。
- **理由**：`git log` 是一条直线，`git diff v0.1.0..main` 能直接反映两次发布之间的全部改动；回滚和二分定位都简单。
- **保障**：GitHub `main` 已开启 `required_linear_history`，违反会被服务端拒绝。

## ADR-006 双远程：GitHub 为主，Gitee 为镜像

- **状态**：已定
- **日期**：2026-11-05
- **决定**：
  - `origin` → GitHub（HTTPS + 凭据管理器），是本地 `main`/`dev` 的跟踪上游
  - `gitee` → Gitee（SSH ed25519），只做镜像与异地备份，不作为开发入口
  - 同步用别名 `git push-all`（推两边 `main`、`dev`）
  - **tag 不随 `push-all` 推送**，发版后单独推两边
- **理由**：GitHub 生态完整（Actions、PR、保护规则），Gitee 国内访问快、免费私有库支持分支保护，两者互补。
- **代价**：两边可能不同步；在 Gitee 网页直接改会造成分叉，**禁止**。
- **注意**：Gitee 曾有自动往默认分支追加 `LICENSE` 提交的行为（见 ADR-010）。

## ADR-007 版本管理：tag 与小程序上传版本号一致

- **状态**：已定
- **日期**：2026-11-05
- **决定**：每次向小程序后台「上传」时，`git tag` 名与填写的版本号完全相同（如 `v0.1.0`），使用附注标签。
- **理由**：线上出问题时，能按版本号直接定位到那次提交；附注标签带作者、时间、说明，比轻量标签可追溯。
- **约定**：版本记录表写在 `README.md` 的「版本记录」一节。

## ADR-008 仓库工程化：LF + UTF-8 + 2 空格 + 忽略个人配置

- **状态**：已定
- **日期**：2026-11-05
- **决定**：
  - `.gitattributes` 统一 `eol=lf`，二进制类型显式声明（本机 Git 系统级 `autocrlf=true`，仓库内已覆盖为 `false`）
  - `.editorconfig` 统一 UTF-8、LF、2 空格缩进
  - `.gitignore` 排除 `project.private.config.json`、`node_modules/`、`miniprogram_npm/`、日志
- **理由**：避免 Windows / macOS 协作出「整个文件都改了」的假 diff；个人配置（基础库版本、`urlCheck`）不能进仓库。

## ADR-009 未决：LICENSE 用哪个

- **状态**：**待定**
- **日期**：2026-11-05
- **现状**：Gitee 在仓库变公开后自动提交了 `LICENSE`（木兰宽松许可证 v2），内容已并入主线（提交 `037d26c`）。
- **需要决定**：
  - **保留木兰 v2**：国产协议，中英文对照，条款接近 Apache 2.0，适合参与国内开源生态
  - **换成 MIT**：更短更通用，个人/学习项目最常见
  - **完全去掉**：仅当仓库转私有；公开仓库无许可证 = 法律上「保留所有权利」，别人不能合法使用
- **操作**：换协议就是替换 `LICENSE` 文件内容并提交一次，无技术风险。

## ADR-010 未决：仓库保持公开还是转私有

- **状态**：**待定**
- **日期**：2026-11-05
- **现状**：GitHub 与 Gitee 均为 public。
- **权衡**：
  - 公开：GitHub 免费账号可享受分支保护；代码对所有人可见
  - 私有：GitHub 免费账号会**失去**分支保护（需要 Pro/Team）；Gitee 免费私有库**仍然支持**分支保护
- **倾向**：单人开发阶段可转私有，把保护规则挪到 Gitee；有协作需求再评估。
